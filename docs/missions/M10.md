**The mission where the player trades memory for time, on purpose, after having measured the
cost themselves.** This is the first genuinely new tool in the product, and it is the only
one that is *earned* rather than introduced.

---

## 1. Briefing (player copy, ES)

> **Memoria del sistema**
>
> Mediste el costo y tenías razón: el detector no aguanta la cola de mañana.
>
> El taller tiene un módulo de memoria que nunca usamos. Guarda valores ya vistos y responde
> "¿esto ya lo tengo?" sin volver a mirar la lista. No es magia: ocupa espacio. Cada valor
> recordado cuesta memoria, y la memoria también se paga.
>
> Quiero que reescribas el detector usando esa memoria. Y esta vez no necesito las
> posiciones: con saber **cuál** es el primer valor repetido me basta para bloquear el lote.
>
> El sistema tiene que aguantar 20.000 órdenes sin que el operador vea el reloj de arena.

**No se menciona:** `Set`, `has`, `add`, tabla hash, O(n). La restricción de escala
("20.000 sin reloj de arena") es la que obliga a cambiar de estrategia.

---

## 2. Contract

```
findFirstDuplicateValue(ids: (string|number)[]) -> string | number | null
```

- Returns the **value** of the first duplicate encountered while scanning left to right.
- "First" = the value whose *second* occurrence appears earliest in the scan.
- Returns `null` when there is no duplicate, including empty and single-element arrays.
- Strict equality only: `'1'` and `1` are different.
- Must not mutate or sort `ids`.

### Why the return type changed

M08 returned `[i, j]`. This mission returns the value. That is not a simplification for
convenience — it is what makes the Set sufficient. To return positions you would have to
remember *where* each value was seen, which is a different structure. That structure is the
next mission.

---

## 3. Constraints

- **Performance budget (hard):** `n = 20.000`, all unique, must complete in **≤ 150 ms** and
  ≤ **100.000** instrumented operations.
- A pairwise solution is correct and fails the budget. That is the intended failure, and the
  diagnosis for it is `E16`.
- No `indexOf`, `includes`, `findIndex` — they are `O(n)` inside a loop and will fail the
  budget anyway, but the explicit ban gives a better message.

## 6. Common mistakes → diagnostics

| Player code | Code | Mentor says |
| --- | --- | --- |
| Reuses the nested loops from M08 | `E16` | "Tu respuesta es correcta y tarda demasiado. Con 20.000 órdenes el bucle interno hace casi 200 millones de comparaciones. La memoria tiene que evitar ese bucle, no hacerlo más rápido." |
| `ids.includes(x)` dentro del bucle | `E16` | "`includes` recorre la lista por dentro. Es el mismo bucle anidado con otro nombre." |
| `new Set(ids).size !== ids.length` para detectar *si* hay duplicado | `E21` | "Eso te dice **si** hay duplicado, pero no **cuál** es el primero. Necesitas recorrer y consultar la memoria en orden." |
| Devuelve el índice en vez del valor | `E12` | "Devuelves una posición. El lote se bloquea con el valor de la orden." |
| `set.has(x)` pero nunca `set.add(x)` | `E07` | "Tu memoria siempre está vacía: nunca guardas nada. ¿Cuándo deberías recordar un valor?" |
| `if (set.has(x)) return x; set.add(x)` invertido | `E07` | "Estás consultando la memoria antes de llenarla. El primer elemento se reporta como duplicado de sí mismo." |

### The shape of the correct solution

```
memoria = conjunto vacío
para cada valor:
    si memoria contiene valor:
        devolver valor        ← ya lo vimos antes
    memoria agregar valor
devolver null
```

Seven lines, and every one of them is load-bearing. The `add` after the check is the most
commonly inverted line in the whole curriculum.

## 7. Hint ladder

**L1**
> El bucle anidado compara cada elemento con todos los anteriores. ¿Qué necesitarías recordar
> para no tener que volver a mirarlos?

**L2**
> Con 20.000 órdenes tu solución hace ~200 millones de comparaciones. ¿Cuántas haría si cada
> elemento se comparara solo con "lo que ya viste"?

**L3**
```
memoria = estructura que responde "¿ya vi esto?" rápido
para cada valor de la lista:
    si memoria dice que ya lo vi:
        devolver ese valor
    guardar el valor en memoria
devolver null
```
El orden importa: primero preguntas, después guardas. Si lo inviertes, todo se reporta como
duplicado.

**L4 — worked variant (isomorphic)**
> Un control de acceso registra los códigos de tarjeta que ya pasaron por el lector, para
> detectar el primer reingreso indebido.
> ```
> function primerReingreso(codigos) {
>   const vistos = new Set();
>   for (let i = 0; i < codigos.length; i++) {
>     if (vistos.has(codigos[i])) {
>       return codigos[i];
>     }
>     vistos.add(codigos[i]);
>   }
>   return null;
> }
> ```
> `Set` responde `has` sin recorrer nada. Ese es el intercambio: memoria a cambio de tiempo.

## 8. Debrief

### The trade, stated plainly

| | M08 (parejas) | M10 (memoria) |
| --- | --- | --- |
| Tiempo | `n(n-1)/2` comparaciones | `n` consultas |
| Memoria | constante | hasta `n` valores |
| 20.000 órdenes | ~200.000.000 operaciones | ~40.000 operaciones |
| 100.000 órdenes | ~5.000.000.000 | ~200.000 |

Ninguna de las dos es "la correcta". La primera no usa memoria y no escala. La segunda usa
memoria y escala. **Elegir entre las dos es el trabajo.**

### Why the memory is not free
Cada valor recordado ocupa espacio. Con 100.000 órdenes distintas, el `Set` guarda 100.000
entradas. En un servidor con miles de usuarios simultáneos, eso es una factura. La pregunta
"¿cuánto estoy dispuesto a gastar en memoria para ahorrar tiempo?" no tiene respuesta
universal.

### Why `Set` and not an object
Un objeto puede hacer de registro, pero tiene problemas: sus claves son strings (así que
`1` y `'1'` colisionan) y hereda propiedades del prototipo (`'constructor'`, `'__proto__'`).
`Set` no tiene ninguna de las dos. Esa es la razón por la que existe.

### The bridge to M11
Pediste el **valor** del duplicado, y por eso bastó con recordar "ya lo vi". Si hubieras
pedido la **posición**, tendrías que recordar también *dónde* lo viste. Eso es guardar un
valor asociado a otro valor — y esa estructura tiene nombre. Es la próxima misión.

### Real world
Deduplicación de eventos, detección de reenvíos, control de idempotencia en APIs, filtros de
"ya procesado", cachés de membresía.

### Reasoning prompt
> Explica el intercambio que hiciste: qué ganaste, qué pagaste, y en qué situación volverías
> a la versión de M08.

`objectiveNouns`: `memoria`, `duplicado`, `velocidad`, `intercambio`
`reasoningLexicon`: `recuerdo`, `consulto`, `intercambio`, `escala`

## 10. Reward

`sys.memory`: **absent → installed**. The workshop diagram gains a memory core. The cost
meter from M09 now shows two numbers for the same job — time and space — and the player can
see the trade in the UI.

## 11. Anti-drift notes

- Do not allow a `Map` here "because it also works". It does work, and it teaches the wrong
  lesson: the player would skip the insight that the value alone is enough. If a `Map` is
  used, accept it functionally but note in the debrief that it stores more than needed.
- The budget must be visible **before** the run, not only in the failure. A player who is
  failed by an invisible constraint learns nothing except to distrust the tests.
- Do not add a third structure (object registry) as an alternative solution path. One new
  tool per mission.
