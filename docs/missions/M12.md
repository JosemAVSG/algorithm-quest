# M12 — La auditoría final

| Field | Value |
| --- | --- |
| id | `M12` |
| world | Transition Arc (gate to World 2) |
| difficulty | 5 |
| primary concept | `C16` strategy-selection |
| secondary concepts | all of World 1 |
| workshop system | `sys.audit` (absent → installed) |
| entry point | `buildAuditReport(orders)` |
| prerequisites | `M09`, `M10`, `M11` |
| est. time | 30–45 min |

**This is the MVP's real exam.** Nothing in the briefing names a structure. The player must
choose three different approaches for three sub-tasks in the same function, and justify the
choice. If the product's thesis is true, this mission proves it. If not, this mission reveals
it before we build six worlds on top.

---

## 1. Briefing (player copy, ES)

> **La auditoría de fin de año**
>
> El contador quiere un informe único de la cola de órdenes del año. Una sola función, un
> solo recorrido del sistema, tres respuestas:
>
> 1. **Órdenes duplicadas**: los `id` que aparecen más de una vez, sin repetirlos en la
>    lista, en el orden en que aparecieron por primera vez. Si una orden aparece cinco veces,
>    el `id` va una sola vez.
> 2. **Conteo por categoría**: cuántas órdenes hay de cada tipo.
> 3. **La orden más prioritaria**: el `id` de la orden con mayor prioridad. Si hay empate,
>    gana la que aparece primero en la lista.
>
> Si la cola está vacía, el informe sale vacío pero **bien formado**: lista vacía, conteo
> vacío, y `null` en la prioritaria.
>
> La cola del año tiene 50.000 órdenes. El contador cierra a las 18:00.

**No se menciona:** `Set`, `Map`, recorrido, dos fases, ninguna estructura. Este es el punto
del ejercicio.

---

## 2. Contract

```
buildAuditReport(orders: Order[]) -> AuditReport

Order = { id: string, category: string, priority: number }

AuditReport = {
  duplicateIds: string[],
  categoryCounts: Map<string, number>,
  highestPriorityOrderId: string | null
}
```

Rules:

| Field | Rule |
| --- | --- |
| `duplicateIds` | ids with count ≥ 2, each once, ordered by **first appearance** |
| `categoryCounts` | every category present, with its count; `Map` preserves insertion order |
| `highestPriorityOrderId` | max `priority`; tie → earliest index; `null` if empty |

- Must not mutate `orders`.
- Must not sort `orders`.
- Hard budget: `n = 50.000` in ≤ **400 ms**.

### Why `Map` is in the return type

Because `categoryCounts` must survive a category called `__proto__`. The contract is
deliberately shaped by M11's lesson. A player who returns a plain object will fail the
hostile-key test, and the diagnosis points back to M11.

---

## 3. Constraints

- Three sub-tasks, one function. No helper modules, no external libraries.
- Helpers *inside* the same file are allowed and encouraged if they clarify.
- No `sort` on `orders` (it mutates). Sorting a derived array of categories is fine.

## 5. Tests

### Visible (3)

| # | Input | Expected |
| --- | --- | --- |
| V1 | `([])` | `{ duplicateIds: [], categoryCounts: Map{}, highestPriorityOrderId: null }` |
| V2 | 3 orders, one duplicate, two categories, clear max priority | correct report |
| V3 | 1 order | `{ duplicateIds: [], categoryCounts: Map{cat:1}, highestPriorityOrderId: id }` |

### Hidden (4)

| # | Input | Expected | Note |
| --- | --- | --- | --- |
| H1 | ids `['A','B','A','B']` | `duplicateIds: ['A','B']` | **order of first appearance**, each once |
| H2 | two orders with equal top priority | the earlier one | tie-break |
| H3 | 6 categories with varied counts | exact map | no category dropped |
| H4 | 50.000 orders | correct + within 400 ms | the budget |

### Edge (3)

| # | Input | Expected | Catches |
| --- | --- | --- | --- |
| ED1 | all 5 orders share one id | `duplicateIds: [thatId]` (length 1) | pushing on every repeat |
| ED2 | no duplicates at all | `duplicateIds: []` | false positives |
| ED3 | category `'__proto__'` present | counted correctly | plain-object registry |

ED1 is the subtle one: a naive implementation pushes the id on *every* occurrence after the
first, producing `[A, A, A, A]` instead of `[A]`.

## 6. The strategy assessment (C16)

After the tests pass, the player answers four questions. These are **not** optional, and they
are what `C16` is actually measuring.

**Q1 — Duplicados.** ¿Qué tuviste que recordar para saber si un `id` ya apareció?
- (a) Nada
- (b) Si ya lo había visto
- (c) Cuántas veces lo había visto
- (d) Dónde lo había visto

**Q2 — Conteo por categoría.** ¿Qué tuviste que recordar?
- (a) Nada
- (b) Si la categoría ya apareció
- (c) Cuántas veces apareció cada categoría
- (d) La posición de cada categoría

**Q3 — Prioridad máxima.** ¿Qué tuviste que recordar?
- (a) Nada
- (b) La mejor orden vista hasta ahora
- (c) Todas las prioridades
- (d) La última orden

**Q4 — Escala.** Si la cola tuviera 5.000.000 de órdenes en vez de 50.000, ¿qué cambiarías?
- (a) Nada, ya escala
- (b) Cambiaría el recorrido por uno más rápido
- (c) Cambiaría la estructura de duplicados por una que no guarde todo en memoria
- (d) Añadiría más memoria al servidor

**Correct answers:** Q1 (b), Q2 (c), Q3 (b), Q4 (c).

Q4 is the only question without a single obviously-correct answer for every context, and it
is scored separately. Answer (a) is defensible if the player justifies that 5M ids in a Set
is acceptable — the assessment accepts (a) **with** a written justification. That nuance is
deliberate: `C16` is about choosing with reasons, not about matching an answer key.

### Scoring

| Score | Condition |
| --- | --- |
| 3 | Q1–Q3 correct **and** Q4 correct or justified |
| 2 | Q1–Q3 correct, Q4 unjustified |
| 1 | 2 of Q1–Q3 correct |
| 0 | otherwise |

`C16` evidence uses this score as its `reasoningScore`.

## 7. Common mistakes → diagnostics

| Player code | Code | Mentor says |
| --- | --- | --- |
| Todo con bucles anidados | `E16` | "Correcto y demasiado lento. Con 50.000 órdenes el bucle anidado hace más de mil millones de comparaciones. ¿Cuál de las tres respuestas necesita recordar algo?" |
| `duplicateIds.push(id)` en cada repetición | `E21` | "Con cinco copias del mismo `id` tu lista tiene cuatro entradas. El contador quiere el `id` una sola vez." |
| `categoryCounts` como objeto literal | `E12` | "La categoría `'__proto__'` rompe el conteo. Es el mismo problema de M11." |
| Devuelve `highestPriorityOrderId` como índice | `E12` | "El contador quiere el `id`, no la posición." |
| Ordena `orders` para agrupar | `E19` | "Ordenar modifica la entrada y además no hace falta para contar." |
| Tres recorridos separados, cada uno correcto | ✅ | *Correct. The mentor says nothing. Three passes is `O(3n)` = `O(n)`.* |
| Un solo recorrido con tres estructuras | ✅ | *Correct and better. The debrief mentions it.* |

The penultimate row matters: **three separate passes is a correct answer** and must not be
criticized. A player who writes three clear loops has understood the problem. Elegance is not
the objective; the objective is choosing the right structure for each sub-task.

## 8. Hint ladder

**L1**
> Tienes tres preguntas distintas en la misma función. ¿Cada una necesita recordar lo mismo?
> Empieza por la que te resulte más clara y no intentes resolver las tres a la vez.

**L2**
> Con `['A','B','A','B']` tu lista de duplicados sale `['A','A']` o `['A','B','A']`. El
> contador quiere `['A','B']`. ¿Qué condición falta antes de agregar?

**L3**
```
para duplicados:      recordar "ya vi este id"        → conjunto
para conteo:          recordar "cuántas veces"        → mapa categoría → número
para prioridad:       recordar "la mejor hasta ahora" → un candidato
```
Tres preguntas, tres formas de memoria. No hay una estructura que sirva para las tres.

**L4 — worked variant (isomorphic)**
> Un informe de una biblioteca: libros repetidos, préstamos por género, y el libro más
> prestado.
> ```
> function informeBiblioteca(prestamos) {
>   const vistos = new Set();
>   const repetidos = [];
>   const porGenero = new Map();
>   let mejorLibro = null;
>   let mejorConteo = 0;
>
>   for (let i = 0; i < prestamos.length; i++) {
>     const p = prestamos[i];
>
>     if (vistos.has(p.libroId) && !repetidos.includes(p.libroId)) {
>       repetidos.push(p.libroId);
>     }
>     vistos.add(p.libroId);
>
>     porGenero.set(p.genero, (porGenero.get(p.genero) || 0) + 1);
>   }
>
>   for (const [genero, n] of porGenero) {
>     if (n > mejorConteo) { mejorConteo = n; mejorLibro = genero; }
>   }
>   return { repetidos, porGenero, mejorLibro };
> }
> ```
> Fíjate en que el desempate de este ejemplo es distinto al tuyo: aquí gana el primero en
> aparecer, no el alfabéticamente menor. **Lee siempre la regla, no la copies de otro sitio.**

The last line of L4 is the most important sentence in the mission. Copying a pattern without
re-reading the rule is exactly the failure mode this curriculum exists to prevent.

## 9. Debrief

### What the three sub-tasks have in common
Ninguna. Y eso es el punto.

| Sub-tarea | Pregunta | Memoria necesaria |
| --- | --- | --- |
| Duplicados | ¿ya vi esto? | conjunto de vistos |
| Conteo | ¿cuántas veces? | mapa valor → número |
| Prioridad | ¿cuál es la mejor hasta ahora? | un candidato |

Un problema real no viene etiquetado. Viene con tres necesidades mezcladas y la obligación de
reconocer cuál es cuál. Eso es lo que acabas de hacer.

### Why 50.000 changes everything
Con 10 órdenes, cualquier solución funciona. Con 50.000, la elección de estructura deja de ser
estética y pasa a ser la diferencia entre terminar y no terminar. La restricción no es un
castigo: es la razón por la que existen las estructuras.

### What "one pass" really means
Un solo recorrido con tres estructuras es `O(n)` en tiempo y `O(n)` en memoria. Tres
recorridos separados también son `O(n)`: la constante es 3, y las constantes no cambian la
forma de la curva. Los dos son correctos. El segundo es más fácil de leer, el primero es más
rápido por un factor pequeño. En un examen, elige el que puedas explicar.

### The honest limitation
Con 5.000.000 de órdenes, guardar todos los `id` vistos ocupa memoria real. La respuesta "usa
un Set" deja de ser obvia, y empiezan a aparecer alternativas (filtros de Bloom, particionado,
procesamiento por lotes). No las vamos a enseñar aquí. Lo que sí importa es saber que el
intercambio tiene un límite.

### Real world
Informes de auditoría, reconciliación de datos, detección de fraude, control de idempotencia,
y cualquier entrevista técnica donde el enunciado no dice qué estructura usar.

### Reasoning prompt
> Elige una de las tres sub-tareas y explica por qué **otra** estructura no habría servido.
> Después di cuál de las tres fue la más difícil de reconocer y por qué.

`objectiveNouns`: `informe`, `duplicado`, `categoría`, `prioridad`
`reasoningLexicon`: `recuerdo`, `elijo`, `estructura`, `intercambio`

## 10. Mastery & transfer

### What this mission decides

| Outcome | Meaning | Consequence |
| --- | --- | --- |
| Pass, ≤1 hint, no reveal, C16 ≥ 2 | The method works | World 2 opens |
| Pass with 2–3 hints | The content works, the ramp is too steep | Tune M10/M11 hints before World 2 |
| Pass only with L4 | The transfer failed | M12 must be redesigned, not the player |
| Fail repeatedly | A prerequisite concept is weak | Reinforcement on the specific concept, not the mission |

This is the only mission in the MVP whose results are a **product decision**, not just a
player statistic.

### Concept effects
- `C16` becomes `transferable` if the mission is `independent` and the strategy assessment
  scores ≥ 2.
- Every World 1 concept with evidence here gains a second context and can reach
  `transferable` if the other conditions hold.
- World 2 opens only if `C16 ≥ introduced` **and** all World 1 primaries are ≥ `practicing`.

## 12. Anti-drift notes

- This mission must never gain a hint in the briefing. The absence of guidance **is** the
  assessment. If playtesting shows players cannot start, fix M10 and M11 — do not add a hint.
- The strategy questionnaire is not decoration. Without it, `C16` has no evidence and the
  mission only measures implementation speed.
- Three correct passes must be accepted without comment. The mentor's silence is a feature;
  a mentor that always has something to say teaches players to ignore it.
