# M01 — El primer diagnóstico

| Field | Value |
| --- | --- |
| id | `M01` |
| world | 1 — Taller de los datos |
| difficulty | 1 |
| primary concept | `C01` condition |
| secondary concept | `C02` boundary |
| workshop system | `sys.sensor` (broken → working) |
| entry point | `isOverLimit(temperature, limit)` |
| prerequisites | none |
| est. time | 4–6 min |

**Purpose: this mission exists to establish the cycle, not to teach an algorithm.**
If a player finishes M01 without ever seeing the diagnosis panel, the mission failed.

---

## 1. Briefing (player copy, ES)

> **Sensor array — turno de noche**
>
> El sensor del horno marca 95 °C. El límite seguro de la línea son 90 °C.
>
> El panel de alarma solo tiene una entrada y espera un sí o un no. Si le mandamos
> cualquier otra cosa, se queda en blanco y nadie se entera del incendio.
>
> Necesito una función que reciba la lectura y el límite, y devuelva si hay que
> disparar la alarma.

**No se menciona:** comparación, operador, booleano. El jugador debe inferir que la
respuesta es un valor de verdad.

---

## 2. Contract

```
isOverLimit(temperature: number, limit: number) -> boolean
```

- Returns `true` when `temperature` **exceeds** `limit`.
- Returns `false` otherwise, **including when they are equal**.
- Must always return a boolean. Never `undefined`, never a string.

### Why "exceeds" and not "reaches"

The word `exceeds` is the entire hidden lesson. A player who reads it as "reaches or
exceeds" writes `>=` and passes every visible test. The boundary test is where they learn
that the natural-language reading of a specification is a skill.

---

## 3. Constraints

- No `Math`, no imports, no helpers.
- Must not throw on any finite number.
- `limit` may be negative (cold-storage sensors).

---

## 4. Starter code

```js
function isOverLimit(temperature, limit) {
  // your code here
}
```

The signature is fixed and non-editable. The player writes the body only — this removes
"did I name the parameter right" noise from the very first mission.

## 6. Common mistakes → diagnostics

| Player code | Code | Mentor says (level 2) |
| --- | --- | --- |
| `return temperature >= limit` | `E05` | "Con 90 y límite 90, el panel recibe `true`. ¿Está el horno por encima del límite, o justo en el límite?" |
| `if (temperature > limit) return true;` (no else) | `E08` | "¿Qué devuelve tu función cuando la condición no se cumple? Compruébalo con 85." |
| `return "true"` | `E12` | "El panel recibe el texto `'true'`, no un valor de verdad. ¿Qué tipo espera?" |
| `return temperature - limit` | `E12` | "Devuelves un número. El panel solo entiende sí o no." |
| `if (temperature) return true` | `E05` | "Con 85 °C y límite 90 el panel se dispara. ¿Qué está comprobando realmente tu condición?" |

The `E08` case is the most instructive: it is the first time the player meets the
"post-condition default" idea that M02 depends on.

---

## 7. Hint ladder

**L1 — conceptual question**
> ¿Qué dos cosas tiene que mirar la función para decidir? ¿Y qué pasa cuando las dos
> son iguales?

**L2 — concrete observation**
> Ejecuta mentalmente tu código con `temperature = 90` y `limit = 90`. ¿Qué devuelve?
> ¿Debería?

**L3 — structural guidance**
```
si  temperature es ESTRICTAMENTE mayor que limit  →  devolver true
si no                                             →  devolver false
```
(La palabra que importa es "estrictamente".)

**L4 — worked variant (isomorphic, different domain)**
> Otro sistema del taller: una puerta de seguridad se bloquea si la presión **supera**
> 3.5 bar. Con 3.5 bar exactos la puerta queda abierta.
> ```
> function debeBloquearse(presion, limite) {
>   if (presion > limite) {
>     return true;
>   }
>   return false;
> }
> ```
> Con 3.5 y límite 3.5 devuelve `false` — la puerta no se bloquea, porque no lo supera.
> Tu sensor funciona igual, con otros nombres.

L4 is a *different* system with different numbers. The player must map it. This is the
authoring rule from `04` §4 and it applies to every mission.

---

## 8. Debrief

### Why it works
Una condición traduce una pregunta del mundo real ("¿está por encima del límite?") a un
valor que el sistema puede usar. La elección entre `>` y `>=` no es sintaxis: es una
decisión sobre el significado de "superar".

### Edge case
En el límite exacto, la alarma no se dispara. Esto es una decisión de diseño, no un
accidente: el límite es *seguro*, y solo lo que está por encima es peligroso. En un
sistema real, esa decisión se documenta, porque alguien la va a cuestionar.

### Cost
Una comparación, siempre. `O(1)`. No importa cuántos sensores haya: esta función mira un
solo valor. Si mañana hay 500 sensores, esta función no es el problema — el problema es
quién la llama 500 veces. (Semilla de M09.)

### Real world
Validación de umbrales: temperatura de CPU, saldo mínimo, latencia máxima aceptable,
límite de rate. Todos son `>` vs `>=` y todos han causado incidentes reales por elegir mal.

### Reasoning prompt
> Explica en una frase por qué con 90 °C exactos la alarma **no** se dispara, y qué
> cambiarías si el taller decidiera que el límite también es peligroso.

`objectiveNouns`: `alarma`, `límite`, `sensor`, `peligro`
`reasoningLexicon`: `comparo`, `supera`, `excede`, `devuelvo`

## 9. Mastery & transfer

- Emits evidence for `C01` (primary, weight 1.0) and `C02` (secondary, 0.6).
- `C02` cannot exceed `introduced` from this mission alone — one boundary case is not
  boundary mastery. It is reinforced in M06 and transferred in M10.
- Transfer of `C01` happens in M12, where the same comparison is buried inside a report
  builder and the player must find it themselves.

---

## 10. Reward

`sys.sensor`: **broken → working**. The workshop diagram's sensor node turns from red to
green and starts emitting readings. The player sees the first system come alive.

No points. No XP. The reward is that the workshop is one system less broken.

---

## 11. Anti-drift notes

- This mission must stay small. If it grows a second concept, it stops being an onboarding
  mission and becomes a gate.
- Do not add a "tutorial overlay" that explains `if`. The strategy prompt and the first
  failed run are the tutorial.
- The first run is *expected* to fail for most players on ED1. That failure is the product
  demo. If telemetry shows >90% pass ED1 on the first attempt, the mission is too easy and
  the visible tests are leaking the answer.
