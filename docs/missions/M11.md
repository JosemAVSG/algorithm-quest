**The mission where the player learns to store a value *associated with* another value.**
In M10 the memory was a set: "have I seen this?". Now it must answer "how many times?".

---

## 1. Briefing (player copy, ES)

> **El índice de categorías**
>
> El taller quiere saber qué tipo de reparación es la más común, para decidir qué repuesto
> comprar en volumen.
>
> Cada orden tiene una categoría. Necesito la categoría que más aparece.
>
> Si hay empate, gana la que va primero alfabéticamente — el jefe quiere una regla fija, no
> "la que salga primero".
>
> Si no hay órdenes, devuelve `null`.
>
> Ojo con una cosa: hay categorías que se llaman `__proto__` y `constructor` porque vienen
> de un sistema viejo. No las ignores.

**No se menciona:** `Map`, `get`, `set`, frecuencia, contador asociativo. La advertencia
sobre `__proto__` está en el enunciado a propósito: es información del dominio, no una pista
sobre la solución.

---

## 2. Contract

```
mostFrequentCategory(orders: {id: string, category: string}[]) -> string | null
```

- Returns the category with the highest number of occurrences.
- Ties are broken **alphabetically ascending** (code-unit order, i.e. `a < b`).
- Returns `null` for an empty array.
- Every category string is valid, including `''`, `'__proto__'`, and `'constructor'`.
- Must not mutate `orders`.

---

## 3. Constraints

- Must handle `n = 20.000` comfortably (soft budget: ≤ 200 ms). No hard operation budget —
  that is M12's job.
- No `sort` of the orders array.
- Sorting the *categories* to break a tie is allowed and is a legitimate solution.

### Edge (3)

| # | Input | Expected | Catches |
| --- | --- | --- | --- |
| ED1 | categories `['', '', 'a']` | `''` | empty string is a valid category |
| ED2 | categories `['__proto__', 'a', '__proto__']` | `'__proto__'` | **plain-object registry** |
| ED3 | categories `['b','a','b','a','a']` | `'a'` | count beats recency |

### Why ED2 is the mission's centre of gravity

A player who writes:

```js
const counts = {};
counts[category] = (counts[category] || 0) + 1;
```

will get `'[object Object]1'` for `'__proto__'`, because `counts['__proto__']` resolves to
`Object.prototype`, not to a stored count. The result is a string, the comparison breaks, and
the answer is wrong in a way that looks like a logic bug but is a *data structure* bug.

The fix is either `new Map()` or `Object.create(null)`. Both are correct. The debrief
explains why `Map` is the better default.

This is not a trick question: the briefing tells the player those categories exist. It is a
real-world hazard that every JavaScript developer meets eventually, and meeting it in a
sandbox with a specific diagnosis is far better than meeting it in production.

## 6. Common mistakes → diagnostics

| Player code | Code | Mentor says |
| --- | --- | --- |
| `const counts = {}; counts[c] = (counts[c] \|\| 0) + 1` con `'__proto__'` | `E12` | "Tu contador devuelve un texto para `'__proto__'`. Un objeto normal hereda propiedades del prototipo y `'__proto__'` no es una clave libre. ¿Qué estructura no hereda nada?" |
| Cuenta bien pero devuelve la primera categoría vista | `E21` | "Con `[a,a,b,b]` devuelves `a` por casualidad. ¿Qué pasa con `[b,b,a,a]`?" |
| Devuelve la última categoría del array | `E21` | "Devuelves la última, no la más frecuente. ¿Dónde estás guardando el máximo?" |
| `counts[c]++` sin inicializar | `E10` | "`undefined + 1` no es 1. ¿Con qué valor empieza cada contador nuevo?" |
| Itera `Object.keys(counts)` pero nunca comparó | `E12` | "Tienes las frecuencias, pero no elegiste la mayor. Falta el segundo recorrido." |
| `orders.sort(...)` para agrupar | `E19` | "Ordenar la entrada modifica la lista original. Además no necesitas ordenar para contar." |

### The correct shape, in two phases

```
fase 1 — contar
    frecuencias = Map vacío
    para cada orden:
        actual = frecuencias.get(categoría) o 0
        frecuencias.set(categoría, actual + 1)

fase 2 — elegir la mayor
    mejor = null
    para cada [categoría, conteo] de frecuencias:
        si mejor es null                        → mejor = categoría
        si conteo > conteoDe(mejor)             → mejor = categoría
        si conteo === conteoDe(mejor) y categoría < mejor → mejor = categoría
    devolver mejor
```

Two phases. This is the first mission where the answer requires *two* passes over derived
data, and that structure is the actual lesson.

## 7. Hint ladder

**L1**
> Para saber cuál es la más común, primero necesitas saber cuántas veces aparece cada una.
> ¿Cuántas cosas distintas tienes que recordar mientras recorres la lista?

**L2**
> Con `['a','a','b']` tu solución devuelve `b`. ¿Estás contando, o estás guardando la última
> que viste? Imprime tu estructura de conteo antes de elegir.

**L3**
```
fase 1: para cada categoría, incrementar su contador
fase 2: recorrer los contadores y quedarse con el mayor
        (en empate, la categoría alfabéticamente menor)
```
Son dos recorridos: uno para contar, otro para elegir. No se pueden mezclar.

**L4 — worked variant (isomorphic)**
> Un lector de códigos postales quiere el código postal más frecuente entre los pedidos de
> un día, con desempate alfabético.
> ```
> function codigoMasFrecuente(pedidos) {
>   const conteo = new Map();
>   for (let i = 0; i < pedidos.length; i++) {
>     const cp = pedidos[i].codigoPostal;
>     conteo.set(cp, (conteo.get(cp) || 0) + 1);
>   }
>   let mejor = null;
>   let mejorConteo = 0;
>   for (const [cp, n] of conteo) {
>     if (n > mejorConteo || (n === mejorConteo && cp < mejor)) {
>       mejor = cp;
>       mejorConteo = n;
>     }
>   }
>   return mejor;
> }
> ```
> El `cp < mejor` es el desempate alfabético. El `mejorConteo` evita tener que volver a
> consultar el mapa.

## 8. Debrief

### Why a Map and not an object
| | Objeto `{}` | `Map` |
| --- | --- | --- |
| Claves | solo strings (los números se convierten) | cualquier valor, sin conversión |
| Herencia | sí (`__proto__`, `constructor`, `toString`) | ninguna |
| Tamaño | hay que contarlo | `.size` |
| Iteración | `Object.keys`, orden especial | orden de inserción, directo |

El objeto no es un diccionario: es un registro con prototipo. `Map` sí es un diccionario.

### Why two phases
Contar y elegir son dos preguntas distintas. Mezclarlas produce el bug clásico: se elige la
categoría "más frecuente hasta ahora", que no es la más frecuente al final. La separación en
fases es una técnica, no un estilo.

### The tie-break
"Alfabéticamente primero" es una regla arbitraria. Su valor no está en ser correcta, sino en
ser **determinista**. Un sistema que devuelve resultados distintos con los mismos datos es
imposible de testear y de depurar.

### Cost
`O(n)` para contar, `O(k)` para elegir (`k` = categorías distintas), `O(k)` de memoria. En el
peor caso `k = n`, y sigue siendo `O(n)`. Comparado con la alternativa ingenua (para cada
orden, recorrer toda la lista: `O(n²)`), es la misma mejora que M10 pero aplicada a un
problema distinto.

### Real world
`GROUP BY` en SQL, conteo de eventos por tipo, análisis de logs, etiquetas más usadas,
`value_counts()` en pandas.

### Reasoning prompt
> ¿Por qué no puedes elegir la categoría más frecuente en el mismo recorrido en que cuentas?
> Explica con un ejemplo de tres órdenes.

`objectiveNouns`: `categoría`, `frecuencia`, `empate`, `índice`
`reasoningLexicon`: `cuento`, `comparo`, `elijo`, `recorro`

## 10. Reward

`sys.index`: **absent → installed**. The workshop diagram gains a category index. From now on
the workshop can answer "how many of each" without scanning, which is the literal capability
that opens World 2.

This is the last capability unlock before the finale, and it is the one that changes the
game's fiction: the workshop is no longer a set of broken machines, it is a system that can
answer questions about itself.

## 11. Anti-drift notes

- Do not require `Map` syntactically. `Object.create(null)` is a valid answer and a good one.
  What is tested is the *behaviour* under hostile keys, not the constructor used.
- Do not add grouping-by-two-keys here. That is World 2 (`C18`) and it needs its own mission.
- The `__proto__` edge case must stay hidden. In the visible tests it would become a hint;
  in the briefing it is domain information; in the diagnosis it is a lesson.
