**The first nested loop.** Everything before this mission was a single pass. This is the
first time the player writes `for` inside `for`, and the first time the cost is genuinely
bad — though they will not be told that until M09.

---

## 1. Briefing (player copy, ES)

> **Órdenes duplicadas**
>
> El sistema de órdenes está metiendo la misma orden dos veces cuando la conexión falla a
> medias. El operador quiere saber **dónde** está el primer par repetido, no cuántos hay:
> con la posición puede cancelar la segunda y seguir.
>
> Necesito las **dos posiciones** en la lista original: la de la primera aparición y la de
> la repetición. La primera es menor que la segunda.
>
> Si no hay ninguna repetida, devuelve `null`.
>
> Importante: `"12"` y `12` **no** son la misma orden. Una es un código de texto y la otra
> es un número interno.

**No se menciona:** comparación por parejas, bucle anidado, O(n²). El requisito de
"posiciones, no valores" es el que fuerza a recorrer con índices.

---

## 2. Contract

```
findFirstDuplicatePair(ids: (string|number)[]) -> [number, number] | null
```

- Returns `[i, j]` with `i < j`, where `ids[i] === ids[j]`.
- "First" means: scanning `i` ascending, and for each `i` scanning `j` ascending from
  `i + 1`, the first pair that matches.
- Returns `null` when there is no duplicate, including empty and single-element arrays.
- Strict equality only.
- Must not mutate or sort `ids`.

---

## 3. Constraints

- No `Set`, no `Map`, no object as a seen-registry. **This mission must be slow.** M10 exists
  precisely because this approach does not scale.
- No `indexOf`, `lastIndexOf`, `includes`, `findIndex`.

### Edge (3)

| # | Input | Expected | Catches |
| --- | --- | --- | --- |
| ED1 | `([1])` | `null` | singleton — inner loop must not run |
| ED2 | `(['1', 1])` | `null` | `==` instead of `===` |
| ED3 | `([1, 2, 2])` | `[1, 2]` | inner pair, `i > 0` |

ED2 is the mission's sharpest test. With `==`, `'1' == 1` is `true` and the answer becomes
`[0,1]`. The briefing states the rule explicitly, so this is a specification-compliance
failure, not a trick.

H4 catches `j < ids.length - 1` — the same off-by-one family as M02's H2, now inside a
nested loop where it is harder to see.

## 6. Common mistakes → diagnostics

| Player code | Code | Mentor says |
| --- | --- | --- |
| `if (ids[i] == ids[j])` | `E22` | "Con `['1', 1]` tu función devuelve `[0,1]`. El enunciado dice que no son la misma orden. ¿Qué operador distingue tipo y valor?" |
| `for (let j = 0; ...)` | `E12` | "Con `[7,7]` devuelves `[0,0]`. Una orden no puede duplicarse a sí misma: la segunda posición tiene que ser posterior a la primera." |
| `for (let j = i; ...)` | `E12` | "Igual que arriba: empiezas comparando el elemento consigo mismo." |
| `return ids[i]` en vez de `[i, j]` | `E12` | "Devuelves el valor. El operador necesita las dos posiciones para cancelar la segunda." |
| `for (let j = i + 1; j < ids.length - 1; j++)` | `E06` | "Con `[1,2,3,4,5,1]` no encuentras nada, porque el último elemento nunca se compara. ¿Hasta dónde tiene que llegar `j`?" |
| Devuelve el *último* par encontrado | `E21` | "Con `[4,5,4,4]` devuelves `[0,3]`. El operador quiere el primero: `[0,2]`. ¿Estás devolviendo en cuanto encuentras?" |
| Usa un objeto o `Set` para recordar vistos | `E19` | "Eso es más rápido y es exactamente lo que vamos a hacer en la próxima misión. Aquí necesitamos la versión lenta para poder medirla." |

The last row is unusual and deliberate: the mentor **names the future solution** as
forbidden. That is not a leak, because M10's briefing will present the Set as the reward for

## 7. Hint ladder

**L1**
> Para saber si una orden se repite, ¿con qué la comparas? ¿Y cuántas comparaciones
> necesitas si hay 5 órdenes? ¿Y si hay 10?

**L2**
> Con `[1,2,3,1]` tu función devuelve `[0,0]`. Mira el valor inicial de `j`: ¿qué posición
> estás comparando contra sí misma?

**L3**
```
para i desde 0 hasta n-1:
    para j desde i+1 hasta n-1:
        si ids[i] === ids[j]:
            devolver [i, j]
devolver null
```
Fíjate en el `i+1`: es lo que impide comparar un elemento consigo mismo y lo que garantiza
que el par salga ordenado.

**L4 — worked variant (isomorphic)**
> Un sistema detecta si un mismo invitado escaneó su entrada dos veces. Necesita los dos
> índices de escaneo, en orden.
> ```
> function primerEscaneoDuplicado(codigos) {
>   for (let i = 0; i < codigos.length; i++) {
>     for (let j = i + 1; j < codigos.length; j++) {
>       if (codigos[i] === codigos[j]) {
>         return [i, j];
>       }
>     }
>   }
>   return null;
> }
> ```

## 8. Debrief

### Why it works
Para encontrar un par hay que comparar cada elemento con los que vienen **después**. Eso
produce un bucle dentro de otro, y el `i + 1` es lo que hace que cada par se compare una sola
vez y en el orden correcto.

### Why the return is inside both loops
A diferencia de M03, aquí sí puedes parar en el primer hallazgo: la pregunta es "¿dónde está
el primero?", no "¿cuáles son todos?". El `return null` final solo se alcanza si ningún par
coincidió.

### Edge cases
- Un solo elemento: el bucle interno nunca se ejecuta, se devuelve `null`.
- `'1'` vs `1`: igualdad estricta. En JavaScript, `==` convierte tipos y produce duplicados
  fantasma; en producción es una fuente real de bugs.
- Duplicado en la última posición: obliga a que `j` llegue a `n - 1`.

### Cost — the seed
Con `n` elementos, el bucle interno hace `n-1`, `n-2`, …, `1` comparaciones. En total
`n(n-1)/2`. Para 10 elementos son 45. Para 1.000 son 499.500. Para 100.000 son casi 5.000
millones.

No vamos a arreglarlo todavía. **La próxima misión es sobre ese número.**

### Real world
Detección de duplicados en importaciones, validación de identificadores, búsqueda de colisiones
en datos sucios, comparación de inventarios entre sistemas.

### Reasoning prompt
> ¿Por qué el bucle interno empieza en `i + 1` y no en `0`? ¿Qué pasaría con `[7,7]` si
> empezara en `0`?

`objectiveNouns`: `par`, `posición`, `orden`, `duplicada`
`reasoningLexicon`: `comparo`, `recorro`, `devuelvo`, `encuentro`
