## 1. Briefing (player copy, ES)

> **Cierre de mes en el almacén**
>
> El almacén lleva tres años con la misma hoja de cálculo y ya nadie sabe cuántas piezas
> hay. Necesito dos números para el cierre:
>
> 1. El **total de piezas** en existencia, sumando todas las líneas.
> 2. Cuántas **líneas están por debajo del mínimo**, que son las que hay que reponer.
>
> El mínimo de reposición son 5 unidades por línea. Una línea con exactamente 5 **no** hay
> que reponerla.
>
> Devuélveme los dos números juntos, no me mandes dos mensajes.

**No se menciona:** acumulador, contador, `+=`, `++`. La forma del retorno (un objeto con
dos campos) es la que obliga a mantener dos valores.

---

## 2. Contract

```
auditInventory(items: {category: string, quantity: number}[])
  -> { total: number, lowStock: number }
```

- `total` = sum of all `quantity`.
- `lowStock` = number of items whose `quantity` is **strictly less than 5**.
- Empty input → `{ total: 0, lowStock: 0 }`.
- Must not mutate `items`.

---

## 3. Constraints

- The literal `5` may appear once in the code, as a named constant. Magic numbers repeated
  in two places are a defect the mentor flags as `E20` (see §6).
- No `reduce`, `filter`, `map`.

## 6. Common mistakes → diagnostics

| Player code | Code | Mentor says |
| --- | --- | --- |
| `for (...) { let total = 0; total += q; }` | `E09` | "Tu total se reinicia en cada vuelta. Con `[10, 2]` debería dar 12 y da 2. ¿Dónde se declara el total?" |
| `let total;` sin inicializar | `E10` | "`total` empieza como `undefined`. `undefined + 10` no es 10. ¿Con qué valor debería empezar?" |
| `if (q <= 5) lowStock++` | `E05` | "Una línea con exactamente 5 unidades no hay que reponerla. Tu código la cuenta. ¿Qué operador lo arregla?" |
| Devuelve `[total, lowStock]` | `E12` | "El cierre espera dos números con nombre, no una lista. ¿Qué estructura permite nombrarlos?" |
| `5` escrito dos veces en sitios distintos | `E20` | "El mínimo está en dos lugares. Si mañana cambia a 8, ¿cuántos sitios hay que tocar?" |
| `items[i].quantity = 0` tras contar | `E11` | "Modificaste el inventario. La auditoría no puede cambiar lo que audita." |

`E20` (duplicated magic constant) is a new code, introduced here because this is the first
mission where a constant has two consumers. It is a warning, not a failure.

## 7. Hint ladder

**L1**
> Necesitas dos números al mismo tiempo. ¿Cuántas variables tienen que sobrevivir desde
> antes del bucle hasta después del bucle? ¿Dónde se declaran?

**L2**
> Con `[10, 2]` tu total da 2 en lugar de 12. Recorre el bucle a mano y mira el valor de
> `total` al final de cada vuelta.

**L3**
```
antes del bucle:
    total = 0
    bajos = 0
para cada línea:
    total = total + cantidad
    si cantidad < 5:
        bajos = bajos + 1
al terminar:
    devolver { total, bajos }
```

**L4 — worked variant (isomorphic)**
> Un gimnasio quiere saber cuántas horas se usaron sus máquinas y cuántas están fuera de
> servicio.
> ```
> function resumenMaquinas(maquinas) {
>   let horas = 0;
>   let fueraServicio = 0;
>   for (let i = 0; i < maquinas.length; i++) {
>     horas += maquinas[i].horasUso;
>     if (maquinas[i].estado === 'rota') {
>       fueraServicio++;
>     }
>   }
>   return { horas, fueraServicio };
> }
> ```
> Dos acumuladores, declarados fuera, devueltos juntos.

## 8. Debrief

### Why it works
Un acumulador es una variable que **sobrevive al bucle**. Si se declara dentro, se destruye
en cada vuelta y solo conserva el último valor. La regla es mecánica: *si el valor debe
existir después del bucle, se declara antes*.

### Two accumulators, two shapes
| | `total` | `lowStock` |
| --- | --- | --- |
| Operación | suma | incremento condicional |
| Cambia en cada vuelta | sí | solo si se cumple la condición |
| Nombre técnico | acumulador | contador |

La diferencia no es de sintaxis (`+= cantidad` vs `++`) sino de *qué se acumula*: una
magnitud o una ocurrencia.

### Edge cases
El caso `quantity: 0` es interesante: el total no cambia, pero el contador sí. Dos
variables que parecían acopladas resultan ser independientes. Ese es el tipo de caso que
rompe una solución que "funcionaba".

### Cost
`O(n)`, una sola pasada, dos operaciones por elemento. Es la forma más eficiente posible
para este problema, y el jugador no lo sabe todavía — se lo diremos en M09.

### Real world
Cierres de inventario, reportes financieros, `SUM` y `COUNT` en SQL (que es exactamente
esta misión, expresada en un lenguaje donde el bucle es implícito), métricas de producto.

### Reasoning prompt
> ¿Por qué `total` tiene que declararse antes del bucle y no dentro? Explica qué pasa con
> el valor en cada vuelta si lo mueves dentro.

`objectiveNouns`: `total`, `mínimo`, `línea`, `cierre`
`reasoningLexicon`: `acumulo`, `sumo`, `cuento`, `sobrevive`
