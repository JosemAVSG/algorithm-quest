**The first mission where the answer is not "the first match" but "the best match".**
The player must hold a candidate while continuing to look — a different mental motion from
M02's early exit.

---

## 1. Briefing (player copy, ES)

> **El tablero de despacho**
>
> Hay una cola de órdenes de trabajo y el despachador solo puede atender una primero. La
> regla del taller es la siguiente:
>
> 1. Gana la orden de **mayor prioridad**.
> 2. Si hay empate, gana la **más antigua** (la que se creó primero).
> 3. Si siguen empatadas, gana la que llegó primero a la cola.
>
> Devuélveme la orden completa, no su posición: el despachador necesita el `id` y los datos
> para imprimir la hoja de trabajo.
>
> Si la cola está vacía, devuelve `null` — el despachador entiende `null`, no entiende una
> orden inventada.

**No se menciona:** recorrido, comparación acumulada, "mejor hasta ahora". La regla de
desempate en tres niveles es la que obliga a mantener un candidato.

---

## 2. Contract

```
findMostUrgent(orders: Order[]) -> Order | null

Order = { id: string, priority: number, createdAt: number }
```

Ordering, highest wins:

1. greater `priority`
2. then smaller `createdAt`
3. then earlier index in the array

- Returns the winning **object**, not its index.
- Returns `null` for an empty array.
- Must not mutate `orders` or reorder it.

---

## 3. Constraints

- Must be a single pass. No sorting.
- No `Math.max`, `sort`, `reduce`.

> Sorting would be correct and is explicitly forbidden: the mission is about maintaining a
> candidate while scanning, which is the skill that later becomes "track the best window".

only test that requires the third rule, and it is hidden on purpose: the briefing states it,

instead of two.

## 6. Common mistakes → diagnostics

| Player code | Code | Mentor says |
| --- | --- | --- |
| `best = null; if (o.priority > best.priority)` | `E02` | "En la primera vuelta `best` es `null` y no tiene `.priority`. ¿Qué comprobación falta antes de comparar?" |
| `best = orders[0]; for (let i = 1; ...)` y devuelve `undefined` con lista vacía | `E08` | "Con la cola vacía tu función devuelve `undefined`. El despachador espera `null`." |
| Solo compara `priority` | `E21` | "Con dos órdenes de prioridad 5, tu función devuelve la primera que encuentra. La regla dice que gana la más antigua. ¿Qué segundo criterio falta?" |
| `Math.max(...orders.map(o => o.priority))` | `E12` | "`Math.max` te da un número, no una orden. Además pierdes el desempate." |
| `return i` (el índice) | `E12` | "Devuelves una posición. El despachador necesita la orden para imprimir la hoja." |
| `orders.sort(...)` | `E19` | "Ordenar resuelve el problema, pero modifica la cola y el ejercicio pide una sola pasada." |
| `best.priority >= o.priority` al actualizar | `E21` | "Con prioridades iguales te quedas con la última. La regla dice que gana la que llegó primero." |

### The three-level comparison, written correctly

```js
function isBetter(candidate, current) {
  if (candidate.priority !== current.priority) {
    return candidate.priority > current.priority;
  }
  if (candidate.createdAt !== current.createdAt) {
    return candidate.createdAt < current.createdAt;
  }
  return false; // tie → keep the current (earlier index)
}
```

The `return false` on a full tie is what makes H3 pass, and it is the part players omit.

## 7. Hint ladder

**L1**
> No puedes saber cuál es la mejor hasta haber visto todas. ¿Qué necesitas recordar
> mientras recorres la lista?

**L2**
> Con `[{p:1},{p:5}]` funciona. Con `[{p:5,t:100},{p:5,t:100}]` devuelves la segunda, y la
> regla dice que gana la primera. ¿Cuántas comparaciones estás haciendo en realidad?

**L3**
```
mejor = null
para cada orden:
    si mejor es null:
        mejor = orden
    si no, si esMejor(orden, mejor):
        mejor = orden
devolver mejor
```
Y `esMejor` compara prioridad; si empatan, compara antigüedad; si empatan, devuelve `false`.

**L4 — worked variant (isomorphic)**
> Un ranking de jugadores: gana quien tiene más puntos; si empatan, quien tiene menos
> partidas jugadas; si siguen empatados, quien se registró primero.
> ```
> function lider(tabla) {
>   let mejor = null;
>   for (let i = 0; i < tabla.length; i++) {
>     const j = tabla[i];
>     if (mejor === null) { mejor = j; continue; }
>     if (j.puntos !== mejor.puntos) {
>       if (j.puntos > mejor.puntos) mejor = j;
>     } else if (j.partidas !== mejor.partidas) {
>       if (j.partidas < mejor.partidas) mejor = j;
>     }
>   }
>   return mejor;
> }
> ```
> En el empate total no se hace nada: se conserva el primero visto.

## 8. Debrief

### Why it works
"El mejor hasta ahora" es un candidato provisional que se reemplaza solo cuando aparece algo
estrictamente mejor. La clave es que la comparación sea **total**: cubre todos los criterios
del enunciado, incluido el último desempate.

### Why the last tie-break matters
Un comparador incompleto no falla: devuelve *alguna* respuesta plausible. Ese es el peor
tipo de bug, porque pasa la revisión y falla en producción con un caso raro. La regla del
tercer nivel existe para que el jugador aprenda que "empate" es un caso, no un accidente.

### Relation to M02
| | M02 | M07 |
| --- | --- | --- |
| Cuándo termina | al primer match | nunca antes del final |
| Qué recuerda | nada | un candidato |
| Retorno | `boolean` | un elemento |

Ambas recorren una lista. Una busca la existencia, la otra busca el extremo.

### Cost
`O(n)`, una pasada, comparación constante por elemento. Ordenar sería `O(n log n)` y además
mutaría la cola — peor en las dos dimensiones. (Semilla para World 3.)

### Real world
Selección de la tarea más urgente, `MAX()` con desempate en SQL, "mejor oferta" en un
comparador de precios, líder de un ranking, selección de la conexión con mejor latencia.

### Reasoning prompt
> ¿Por qué no puedes devolver una respuesta antes de terminar el recorrido? Usa un ejemplo
> donde la mejor orden esté al final.

`objectiveNouns`: `orden`, `prioridad`, `antigua`, `despachador`
`reasoningLexicon`: `comparo`, `recuerdo`, `reemplazo`, `recorro`

## 11. Anti-drift notes

- The three-level tie-break is the mission. If playtesting shows it is too fiddly, reduce to
  two levels — do **not** remove the tie-break entirely, or `C10` collapses into `C09`.
- Do not accept a sorting solution "because it works". The single-pass constraint is what
  makes this a scan-best mission instead of a sorting mission, and sorting arrives in World 3
  with its own invariant lesson.
