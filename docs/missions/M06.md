**The first mission where the player does not write a function from scratch.** They read
code that looks correct, and it is not. This is a different cognitive act, and it is the
one most interview candidates have never practised.

---

## 1. Briefing (player copy, ES)

> **El guardia de seguridad no confía en el promedio**
>
> El sistema de seguridad calcula la temperatura media del turno. Si el promedio pasa de
> cierto valor, bloquea la línea.
>
> El problema: el promedio a veces sale `NaN` y el guardia se queda esperando para siempre.
> Y cuando hay sensores desconectados, el promedio sale raro pero *no* da error, así que
> nadie se enteró durante meses.
>
> La función la escribió un becario. **Funciona en los casos normales.** Tu trabajo no es
> reescribirla: es encontrar por qué falla en los casos raros y arreglarlo.
>
> Reglas del taller:
>
> - Un sensor desconectado llega como `null` y **no debe contar** para el promedio, ni en
>   la suma ni en la cantidad.
> - Si no hay ninguna lectura válida, el promedio es `null` (el guardia entiende `null`,
>   no entiende `NaN`).

**No se menciona:** caso vacío, división por cero, filtrado. El jugador debe leer el código
y descubrir que el denominador no distingue lecturas válidas de inválidas.

---

## 2. Given code (the defect)

```js
function averageTemperature(readings) {
  let sum = 0;
  for (let i = 0; i < readings.length; i++) {
    sum += readings[i];
  }
  return sum / readings.length;
}
```

### The two defects, and why they are one defect

| Symptom | Cause | When it appears |
| --- | --- | --- |
| Returns `NaN` | `0 / 0` | Empty array |
| Average too low | `null` counts in the denominator but adds 0 | Any array with `null` |

Both come from the same root: **the denominator counts entries, not valid entries.** The
mission is designed so that a player who fixes only the `NaN` (the visible symptom) still
fails the hidden tests. That is the difference between patching a symptom and finding a
cause.

---

## 3. Contract (what the fixed function must do)

```
averageTemperature(readings: (number|null)[]) -> number | null
```

- Ignore `null` entries entirely (neither sum nor count).
- Return the arithmetic mean of the remaining values.
- Return `null` when there are no valid values (including empty input).
- Must not mutate `readings`.

## 4. Tests

### Visible (3)

| # | Input | Expected | Note |
| --- | --- | --- | --- |
| V1 | `([20, 30])` | `25` | happy path — passes already |
| V2 | `([10])` | `10` | singleton — passes already |
| V3 | `([])` | `null` | **the visible symptom** |

### Hidden (4)

| # | Input | Expected | Note |
| --- | --- | --- | --- |
| H1 | `([20, null, 30])` | `25` | the silent bug |
| H2 | `([null])` | `null` | no valid values, non-empty |
| H3 | `([0, 0])` | `0` | zero is a valid value |
| H4 | `([-10, 10])` | `0` | negatives |

### Edge (3)

| # | Input | Expected | Catches |
| --- | --- | --- | --- |
| ED1 | `([null, null, null])` | `null` | `sum / length` still runs |
| ED2 | `([5.5])` | `5.5` | integer assumptions |
| ED3 | `([1e9, 1e9])` | `1e9` | precision / overflow assumptions |

H3 is the one that punishes the lazy fix `if (!readings[i]) continue`. Zero is falsy, so
that fix silently drops valid readings. This is the mission's second trap and it is
deliberate.

## 5. Common mistakes → diagnostics

| Player code | Code | Mentor says |
| --- | --- | --- |
| `if (readings.length === 0) return null;` **solo** | `E04` | "Arreglaste el `NaN`, pero `[20, null, 30]` sigue dando 16.67 en vez de 25. ¿Qué representa el denominador en tu división?" |
| `if (!readings[i]) continue;` | `E05` | "Con `[0, 0]` tu función devuelve `null`. El cero es una lectura válida: está frío, no desconectado. ¿Qué comprobación distingue `0` de `null`?" |
| `if (Number.isNaN(result)) return null;` | `E04` | "Eso convierte el síntoma en `null`, pero el promedio de `[20, null, 30]` sigue mal. El `NaN` era la pista, no el problema." |
| Reemplaza `null` por `0` | `E05` | "Un sensor desconectado no mide 0 °C. Contarlo como 0 hunde el promedio y puede bloquear la línea sin motivo." |
| Reescribe toda la función con `filter` | `E19` | "La solución es correcta, pero el ejercicio pide encontrar y corregir el defecto. Reemplazar el código entero evita el diagnóstico." |
| `readings.length = 0` o `readings.pop()` | `E11` | "Modificaste las lecturas originales para que la división funcionara." |

### Why "rewrite it" is rejected here

This is the only mission that rejects a full rewrite. The learning objective is
`C15` — *reading* code and locating a defect. A rewrite demonstrates that the player can
solve the problem, not that they can diagnose it. The rejection is soft: the player is told
why, and may keep the rewrite after acknowledging it (it still scores, but `C15` evidence is
recorded with `rewriteDetected: true` and does not exceed `practicing`).

## 6. Hint ladder

**L1**
> La función falla de dos maneras distintas. ¿Crees que tienen la misma causa o dos causas
> separadas? Empieza por explicar qué representa `readings.length` en la última línea.

**L2**
> Con `[20, null, 30]`: suma 50, divide entre 3. ¿Cuántas lecturas **válidas** hay? ¿Por qué
> el denominador no coincide?

**L3**
```
contador de válidas = 0
suma = 0
para cada lectura:
    si la lectura es null:
        saltar        ← no suma, no cuenta
    suma += lectura
    válidas += 1
si válidas === 0:
    devolver null
devolver suma / válidas
```
Dos variables que antes eran una: `length` se convierte en `válidas`.

**L4 — worked variant (isomorphic)**
> Un sistema calcula el ticket promedio de un restaurante, pero algunas mesas no dejaron
> propina y llegan como `null`. Deben excluirse del promedio, no contarse como cero.
> ```
> function propinaPromedio(propinas) {
>   let suma = 0;
>   let validas = 0;
>   for (let i = 0; i < propinas.length; i++) {
>     if (propinas[i] === null) continue;
>     suma += propinas[i];
>     validas++;
>   }
>   if (validas === 0) return null;
>   return suma / validas;
> }
> ```
> El defecto era el mismo: dividir entre el total en vez de entre las válidas.

## 7. Debrief

### Why it works
El denominador de un promedio no es "cuántos elementos hay", es "cuántos elementos
cuentan". Esa distinción es la que separa un promedio correcto de uno que parece correcto.

### Why the bug survived months
Porque el código **funciona en los casos normales**. Un bug que solo aparece con datos
sucios es el más caro de encontrar, y el más común en producción. La lección no es "usa
`null` checks"; es "pregúntate qué supone tu código sobre los datos que recibe".

### The two traps
1. Arreglar el `NaN` y no el promedio (síntoma vs causa).
2. `if (!x) continue`, que trata `0` como inválido (falsy vs nullish).

Ambas son la misma familia de error: confundir "ausencia de valor" con "valor que
evaluamos como falso". En JavaScript esa confusión es endémica.

### Edge cases
Sin lecturas válidas → `null`. No `0`, no `NaN`. El contrato con quien llama importa tanto
como el cálculo: `null` significa "no hay dato", `0` significa "el dato es cero".

### Cost
`O(n)`, una pasada. La corrección no cambia el costo; cambia el significado.

### Real world
Promedios con datos faltantes, métricas de producto con eventos no instrumentados,
`AVG` en SQL (que ya ignora `NULL`, exactamente por esta razón), limpieza de datasets.

### Reasoning prompt
> Explica por qué `[20, null, 30]` da 16.67 con el código original y 25 con el tuyo. ¿Qué
> cambió exactamente en la división?

`objectiveNouns`: `promedio`, `sensor`, `válida`, `null`
`reasoningLexicon`: `divido`, `cuento`, `ignoro`, `excluyo`

## 10. Anti-drift notes

- This mission must never gain a third defect. Two, both traceable to one root cause, is the
  maximum a player can hold while also learning to read unfamiliar code.
- Do not show the tests before the player reads the code. The intended sequence is
  read → hypothesize → run → confirm. If the test panel opens first, the mission becomes
  guess-and-check.
- The "reject a rewrite" rule is the most fragile design decision in World 1. If telemetry
  shows players rewriting and getting stuck, soften it to advisory rather than blocking.
